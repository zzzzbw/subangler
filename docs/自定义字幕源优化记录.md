## 一、ASSRT 伪射手（`assrt`）

### 2026-11-24 · 按 filelist 单文件评分 + 精确下载对应集

- **提交号**：`a2b843b`（`feat: ASSRT 按 filelist 单文件评分并精确下载对应集`）
- **改动文件**：`src/subangler/providers/custom/assrt.py`、`tests/test_custom_providers.py`

#### 问题现象

任务 #10 下载《辐射》(2024) S01E02 时，ASSRT 源在打分阶段返回 0 个可用候选，字幕未下载。此前诊断该源候选普遍评分只有 10~35 分，全部低于自动下载阈值（`providers.min_score = 60`）。

#### 根因（三层，本次解决第 3 层）

1. **中文标题归一化失效（评分器结构缺陷，未在本项目前次改动）**：`UnifiedScorer` 的 `_norm()` 正则只保留 `[a-z0-9]`，中文片名被过滤成空串。实测 `_norm("辐射") == ""`，导致 title（20+5 分）和 release（15 分）对中文剧集几乎恒为 0。
2. **fps 恒为 0**：ASSRT 的 `Candidate` 不携带帧率，帧率维度 10 分固定拿不到。
3. **合集匹配粒度错误（本次核心问题）**：ASSRT 搜索返回的往往是「全季合集」条目，例如 id=718018 `辐射第一季全8集 ... S1 ... 中文字幕`。**其 `filelist` 里其实就有正确文件** `Fallout (2024) - S01E02 - The Target ... .chs.srt`，但旧代码用外层的 `videoname`（没有单集号）作为 `release_name` 打分，guessit 解析不出 episode，episode 维度 30 分全部丢失。搜索结果是对的，匹配粒度错了。

#### 改动内容

- **search 按单文件生成候选**：`filelist` 里每个可下载字幕文件（`_SUB_EXTS = srt/ass/ssa/vtt`，跳过 `._` 资源叉文件）生成一个独立候选，`release_name` 用文件名本身，使 guessit 能解析出 S01E02。
  - `external_id = "{sub_id}|{index}"`，具体文件标识写入 `extra = {sub_id, file_index, file_name, native_name, revision}`。
  - 无 `filelist` 的旧响应仍按整个条目评分，保持向后兼容。
- **单文件语言判定 `_file_language_ok()`**：从文件名 token 判断语言，命中目标语言关键词保留；出现明确的其他语言标记（`spa/fre/ger/...`）则排除，避免「37 语言包」生成大量无关候选。
- **按 (季, 集) 归并去重 `_episode_key()`**：同一字幕条目内常含 chs/cht/双语变体，用 guessit 解析出的 `(season, episode)` 归并，每个集只保留得分最高的一条；解析不出时回退文件名。
- **download 精确下载**：detail 接口的 `id` 取 `extra.sub_id`（去掉 `|index` 后缀），再按 `extra.file_index` 从 detail 的 `filelist` 精确取对应文件下载；旧候选（无文件标识）回退取第一个可下载字幕文件。
- **健壮性**：`vote_score` / `size` 的 `int()` 换为 `_safe_int()`，避免脏值抛异常。

#### 验证结果

- 用抓自 ASSRT 的真实响应（搜索词 `辐射 - S01E02 - 第2集`，HTTP 200，15 条 sub）回放：
  - S01E02 候选从 **35 分 → 66 分**（season 25 + episode 30 + year 10 + release 1），超过 60 阈值，排名第一，可自动下载。
  - 候选数从 134 降到 36（zh）/ 28（en），候选页不再被重复文件淹没。
  - 精确下载验证：指定 `file_index=7`，实际请求的是 `S01E02 - The Target.chs.srt`，而非旧逻辑固定取的第一个（S01E03）。
- 全量 `pytest` **92 项通过**（新增 5 个针对性测试：单文件评分、S01E02 最高分、按 index 精确下载、多语言筛选、旧候选兼容）。
- 需重启 8765 服务后新逻辑生效。

#### 遗留 / 后续方向

- 根因 1、2（评分器对中文标题、缺失 fps 的处理）属于 `UnifiedScorer` 通用缺陷，见第四节。修好后中文剧集还能再拿回约 40 分。
- 本次未改动 Zimuku / SubDL，因为它们不返回「全季合集 + 单文件列表」结构（见各源小节）。

### 2026-11-24 · 修正测试连接接口 + 凭证明文显示

- **提交号**：`5f91204`（`fix: 修正 ASSRT 测试连接接口并支持凭证明文显示`）
- **问题**：① 「测试连接」请求了官方不存在的 `/v1/user/info`，返回 `20400 API endpoint not found`；② 配置页「显示」按钮只是把密码框切成文本框，看到的是库里存的掩码串。
- **改动**：
  - 测试连接改为 `GET /v1/user/quota`，认证用 `Authorization: Bearer <token>`，并从 `providers.assrt_base_url` 读取地址；正确解析 JSON 显示剩余配额或 `errmsg`。
  - 新增需登录的 `POST /api/config/reveal` 按需返回明文；前端「显示」调用该接口取真实 token，「隐藏」清除明文；测试连接遇掩码值也先取明文。
- **验证**：后端测试 85 项通过；浏览器实测显示/隐藏/测试连接均正常。

## 三、Zimuku 字幕库（`zimuku`）

- 网页抓取型源，search 用搜索结果页标题作为 `release_name`，单条目单候选；详情页再解析下载链接。无 `filelist` 结构，暂不涉及按单文件评分。
- 2026-11-24：`FlareSolverr` URL 改用 `normalize_flaresolverr_url()` 拼接 `/v1`，修复配置了结尾斜杠时出现 `/v1/v1` 的问题（提交 `43e7314`）。
- 已知痛点：Zimuku 有验证码/反爬，搜索往往在到达打分前就失败（任务 #10 日志中即如此）。若要提升该源成功率，后续需单独处理 FlareSolverr 挑战流程。

## 四、通用能力（影响所有源，非单源优化）

### 2026-11-24 · season 取值笔误 + 打分容错

- **提交号**：`3282720`
- **问题**：`video_to_dict()` 把 `season` 错取成 `video.series`（剧名，如「辐射」），导致全库 875 条视频 season 存成剧名字符串；打分器 `int(want_season)` 抛 `ValueError`，拖垮所有走 `UnifiedScorer` 的自定义源。
- **改动**：`season` 改取 `video.season`；新增 `_safe_int()`，season/episode/year 的比较全部走安全转换，脏数据只让该项计 0 分，不再崩溃。
- **数据遗留**：用户选择「只修代码」，历史 875 条脏 season 未修，需重新扫描媒体库覆盖入库（用户已重新扫描，抽查视频 868/869/870 的 season 已为正确的 `1`）。

### 待优化（评分器结构缺陷，尚未实施）

- **中文标题归一化**：`_norm()` 正则 `[a-z0-9]+` 丢弃中文。可考虑保留 CJK 字符，或对中文标题走字符级相似度，让中文剧集拿回 title 的 25 分。
- **release 维度对中文不友好**：同上，词级 Jaccard 对中文失效（15 分）。
- **fps 缺失**：字幕源普遍不携带帧率，该 10 分几乎所有自定义源都拿不到；可考虑缺失时给中性分而非 0 分。
- **合集识别**：「全 N 集」条目无单集号时 episode 计 0；ASSRT 已通过拆分 filelist 绕过，其他源如遇同类结构可复用该思路。
